# Strategy Experience Advice

## 这个 skill 是做什么的

这个 skill 的作用，不是总结历史轨迹，也不是复述过去做过什么。\
它要做的，是把已经召回出来的历史 trajectory 转化成一份**面向当前任务的策略型经验建议**。

这份建议应当帮助 agent 回答这样几个更关键的问题：

当前任务本质上到底是什么问题。\
历史经验里哪些部分真的能迁移到这次任务。\
这次任务更合理的起手方式和推进顺序是什么。\
执行过程中最可能出现哪些误判、冲突或低效路径。\
哪些部分已经有经验支撑，哪些部分其实还需要继续探索。

换句话说，这个 skill 充当的不是“历史摘要器”，而是一个**行动前的判断层**。\
它的价值在于先帮助 agent 看懂当前问题，再帮助 agent 决定接下来怎么做。

## 使用这个 skill 时要重点关注什么

生成建议时，最重要的不是先看历史轨迹，而是**先看当前任务**。

历史轨迹只是经验来源，不是现成答案。\
不能因为 tags 相似、关键词相似，就默认这些轨迹可以直接套到当前任务上。\
真正要比较的是：任务目标是不是一致、产出物是不是一致、约束是不是一致、难点是不是同一类、执行环境是不是接近。

一个好的输出，应该始终围绕四件事展开。

第一，是把当前任务重新看清楚。\
不要机械复述用户原话，而要说明这次任务真正要解决的是什么问题，最终要产出什么，难点落在哪，哪里最容易误判。很多任务失败，不是因为缺经验，而是因为一开始就把问题看错了。

第二，是判断历史经验和当前任务之间到底是什么关系。\
有些经验可以直接借鉴，有些经验只有在特定条件下才成立，还有一些经验虽然不能直接复用，但可以提醒当前任务中最可能出现的错误。这个区分，比简单列出“相似轨迹”更重要。

第三，是把经验重新组织成当前任务的行动建议。\
输出不能停留在“过去通常怎么做”这种抽象层，而要进一步落到：当前任务先做什么、后做什么、每一步在解决什么问题、适合调用什么工具或能力。

第四，是明确经验的边界。\
如果召回到的历史轨迹只能覆盖当前任务的一部分，就必须老实写出来。这个 skill 不应该制造一种“经验已经足够”的假象，而应该指出哪些部分仍然需要检索、试探、验证或探索。

## 这个 skill 的内部思路

这个 skill 在内部应当遵循一种很简单的思路：

先把当前任务理解成一个“问题”，而不是一句“需求描述”；\
再把召回轨迹看成可能提供帮助的经验来源，而不是标准答案；\
接着从这些经验中筛出对当前任务真正有价值的部分，把它们重组为策略和行动建议；\
最后说明哪些地方可以放心沿用经验，哪些地方还不能，必须继续探索。

这个过程应当体现在最终输出里，但不要把输出写成思维链，也不要写成机械的流水线 checklist。\
最终产物应当读起来像一份清楚、克制、能指导执行的策略说明。

## 什么样的输出算是好的

好的输出应该有一种很明确的感觉：\
它让 agent 更清楚当前任务到底是什么；\
它解释了为什么某些历史经验值得参考、为什么另一些不该直接照搬；\
它把经验落成了当前任务可执行的行动顺序；\
它在真正开始执行之前，就提前标出了最可能出问题的地方；\
它还会清楚写出经验覆盖不到的部分，不会拿旧经验冒充确定答案。

输出语言要具体、平实、可执行。\
避免出现“结合实际情况灵活调整”“具体问题具体分析”这类空泛表述。\
所有内容都应尽量紧贴当前任务本身。

## 输出格式

请严格使用下面的 markdown 结构输出，写入到`~/.claude/learn-once/state/active_suggestion.md`文件中：

```markdown
# 面向当前任务的策略型经验建议

## 当前任务理解
**任务重述：**  
<用自己的话重述当前任务，强调它真正要解决的问题、目标和产出物>

**问题本质：**  
<说明当前任务本质上属于什么问题，例如任务识别、策略选择、工具调用、经验迁移、探索型问题等>

**关键约束与难点：**  
<用一小段完整的话说明当前任务最重要的限制、判断难点或执行难点>

## 历史经验对当前任务的意义
**可以直接借鉴的经验：**  
<说明哪些经验可以直接迁移，以及为什么它们适合当前任务。必要时标注 trajectory_id>

**需要条件化使用的经验：**  
<说明哪些经验只有在某些前提成立时才适用，并指出这些前提是什么。必要时标注 trajectory_id>

**更适合作为风险提醒的经验：**  
<说明哪些历史轨迹不适合直接照搬，但能提醒当前任务中可能出现的误判、冲突或低效路径。必要时标注 trajectory_id>

## 这类问题通常如何处理
<用一段完整的话概括这类问题通常的解题方式：一般先判断什么，再处理什么，为什么不能直接执行，常见的策略节奏是什么>

## 针对当前任务的建议行动
**总体策略：**  
<用一两句话写清这次任务最推荐的处理思路>

**建议的起手动作与推进顺序：**  
1. <先做什么>。目的在于：<为什么>。可调用：<工具/能力>。  
2. <再做什么>。目的在于：<为什么>。可调用：<工具/能力>。  
3. <接着做什么>。目的在于：<为什么>。可调用：<工具/能力>。  
4. <最后做什么>。目的在于：<为什么>。可调用：<工具/能力>。  

## 执行中可能遇到的问题
<用一段或几段简洁说明，指出当前任务最可能出现的误判、阻塞点、冲突点，以及相应的处理策略>

## 当前经验的边界
**已有经验足以支持的部分：**  
<说明哪些部分可以较有把握地依据已有经验推进>

**只能提供弱参考的部分：**  
<说明哪些部分虽然有相似经验，但不足以直接下结论>

**需要继续探索的部分：**  
<说明哪些部分超出了历史经验的覆盖范围，需要进一步检索、验证、试探或探索>

## 一句话结论
<用一句完整的话总结：当前任务最应该如何理解、最应该如何起手，以及最该警惕什么>
```

## 使用边界

如果当前任务本身很简单，直接处理就可以，不需要借助历史经验，那就不必使用这个 skill。\
如果用户要的是轨迹归档、案例汇总、知识库整理，而不是面向当前任务的策略建议，也不适合使用这个 skill。\
如果任务要求的是事实核验，而历史轨迹只能提供方法经验，也不能让历史经验替代外部证据。

当召回到的 trajectory 很弱、很稀疏，或者只是表面相关时，输出中必须明确说明：当前建议只能提供部分参考，不能把它写成高确定性的结论。

## 最小调用方式

当你已经有：

- `current_task`
- `retrieved_trajectories`

可以这样调用这个 skill：

“请基于当前任务和召回轨迹，生成一份面向当前任务的策略型经验建议。重点不是总结历史，而是帮助 agent 更准确地理解当前问题、判断哪些经验可迁移、形成行动建议，并指出风险边界与需要探索的部分。请严格按照 skill 中定义的 markdown 模板输出。”

## 一句话提醒

这个 skill 不是用来总结过去的，\
而是用来把过去的经验转换成当前任务可执行的判断和行动建议。
